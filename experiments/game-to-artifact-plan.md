# Proposal: Institutionalizing the design→solve→ship loop

> Status: proposal (experiment-grade, produced by a planning agent from the two
> completed instances — Green Lane and Undertow). Promotion of any part into
> `cardlang/` or `tests/` follows the repo's corpus-first doctrine and the
> surface-totality gate. Companion evidence: `green-lane/REPORT.md`,
> `undertow/REPORT.md`.

## Goal and non-goals

**Goal.** Turn the pattern proven twice — design a game in the DSL outside the corpus, evaluate it through the OpenSpiel adapter (exact battery for small games, probe battery for large ones), then ship a self-contained playable artifact with a measured AI opponent — into repeatable infrastructure: a designer CLI that checks, runs, simulates, and **plays** any game file straight from the terminal; a promoted, gate-covered evaluation library (`cardlang/lab/`); a shared artifact kit with mechanical drift protection (differential fixtures); and a scaffolded per-experiment workflow. Extract, don't rewrite: `glcommon.py`/`utcommon.py`, `solve.py`, `proofs.py`, the `analyze_*` scripts, and the Green Lane play template are the source material, and the repo's promotion doctrine (corpus-first, promote at second/third instance) decides what moves into the package versus what stays experiment-grade. A recorded **secondary objective**: the same derived-view architecture should make cardlang games offerable to the MARL/RL research ecosystem as first-class environments — the named path is the top of "Future runtimes and targets" at the end of this document.

**Non-goals.** No changes to corpus-adapter or runtime *semantics* — the CLI consumes seams that already exist (`Chooser`, `play_game`'s tracer/observer hooks, `replay.run`), and any genuinely new hook is named in its phase and gate-covered; no changes to the grammar or the corpus games; no per-game code in the package; no TUI-framework or curses dependency (plain line I/O — the core install stays lark-only, and `play`/`run`/`simulate` must work without the `openspiel` extra); no shipped-artifact LLM capability or network access (strict-CSP, self-contained pages stay the contract); no attempt to make tabular solver output deployable beyond small games; no automation of the genuinely creative steps (game design, UI art direction, DESIGN/REPORT prose, heuristic invention). CI stays exactly `mypy` (bare) + `pytest -q`; `experiments/` stays outside both gates.

## Quick start (the target UX)

Try a game — two commands, no OpenSpiel build, no Python authored:

```
uv tool install cardlang        # once published; today, from a checkout: uv tool install .
cardlang play hearts            # take seat 0 in a full game of Hearts, other seats random
```

(Zero-install variant from a checkout: `uv run cardlang play hearts` — uv builds the env from `pyproject.toml` on demand. `cardlang list` names every packaged game.)

Poke at it before committing an evening:

```
cardlang run hearts --seed 7 --trace     # watch one full random game, events narrated
cardlang simulate hearts -n 1000         # score distributions, lengths, branching
cardlang play hearts --vs cmd:"claude -p"    # seat an LLM as an opponent (any chat CLI or API)
```

Design a game — the same loop, pointed at your own file:

```
cardlang new rip-current                                  # scaffold experiments/rip-current/
$EDITOR experiments/rip-current/rip-current.cardlang
cardlang check experiments/rip-current/rip-current.cardlang       # full front end: parse → resolve → typecheck
cardlang play  experiments/rip-current/rip-current.cardlang       # feel it immediately
cardlang simulate experiments/rip-current/rip-current.cardlang -n 500
cardlang lab   experiments/rip-current/rip-current.cardlang --out results.json   # the full battery (needs the openspiel extra)
cardlang lab train experiments/rip-current/rip-current.cardlang --mccfr 200000 --out brain.json
cardlang play  experiments/rip-current/rip-current.cardlang --vs brain.json      # play against the AI you just trained
```

Everything below `play`/`simulate` in that list is the existing plan; the CLI rows are P0.

## The per-game workflow after the infrastructure exists

A designer's-eye walkthrough, from `.cardlang` to published artifact. Steps marked **[1 cmd]** are single commands; unmarked steps are creative work.

1. **Scaffold.** `cardlang new rip-current` **[1 cmd]** — copies `experiments/_template/` to `experiments/rip-current/`: `DESIGN.md` skeleton, `rip-current.cardlang` stub, `REPORT.md` skeleton with the honesty-ledger section preprinted, `probes.py` stub (game-specific probe plugs), `opponent.py` stub, `play/` with the kit page template, `variants/`.
2. **Design.** Write `DESIGN.md` and the game file(s), including a `-mini` reduction if a small-state exact solve is wanted. `cardlang check experiments/rip-current/rip-current.cardlang` **[1 cmd]** checks it through the full front end.
3. **Playtest.** `cardlang play experiments/rip-current/rip-current.cardlang` **[1 cmd]** — sit in the game the moment it type-checks, before any solver runs. `cardlang run --seed 7 --trace` **[1 cmd]** replays a full random game with narrated events (rule bugs surface here as "wait, why was that legal?"); `cardlang simulate -n 500` **[1 cmd]** eyeballs score balance, game length, and decision liveness. This is the tight inner loop: edit → check → play.
4. **Evaluate.** `cardlang lab experiments/rip-current/rip-current.cardlang --out experiments/rip-current/results.json` **[1 cmd]** (a bare game path runs the `eval` battery; `lab` is a subcommand family, and every lab-side step from here on stays under it). The battery self-tiers: it registers the game (declared-or-verified utility, configurable seed sampling), runs smoke shape (lengths, branching, seat balance, zero/constant-sum verification, sample infostates), the four generic info-set proofs, then either the **exact tier** (budgeted census → CFR+ with exploitability trend → game value, mixedness, reach-weighted top decisions, naive-grid-vs-best-response using the rules plugged in `probes.py`) or the **probe tier** (decision-liveness by ply, obs-log-driven probes from `probes.py`, MCCFR training + skill gradient + head-to-head arena). One JSON out, REPORT-ready. Long stages obey the long-run contract (P2): the stage plan with time estimates prints before work starts, progress lines carry the live metric, and `results.json` fills stage-by-stage — an interrupted battery keeps every finished stage. Variants: same command per file in `variants/`.
5. **Iterate.** Read `results.json`, red-team, write variants, re-run steps 3–4 per variant, record the round in `REPORT.md`. A suspicious solver line is a `cardlang run --seed N --trace` away from being watched, and a proposed fix is a `cardlang play` away from being felt.
6. **Choose and benchmark the opponent.** Fill in `opponent.py` (a policy over the adapter's `Pause`, parameters explicit). `cardlang lab arena experiments/rip-current/opponent.py --vs equilibrium,best_response,mccfr:120000,random --out opponent-bench.json` **[1 cmd]** produces the measured strength claim (exact deviation/BR loss when the tree fits; head-to-head means ± stderr when it doesn't). Sanity-check it by hand: `cardlang play --vs experiments/rip-current/opponent.py` **[1 cmd]** seats you against the tuned policy — and any generated AI seats the same way (`--vs brain.json`, `--vs play/policy.json`, or a per-seat mix like `--vs 1=brain.json,2=random,3=random`). For a tabular opponent, `cardlang lab policy-export ...` **[1 cmd]** solves, canonicalizes keys, proves key injectivity, writes `play/policy.json`, and re-verifies the exported table's exploitability. For PIMC, the same `arena` subcommand benchmarks `cardlang.lab.pimc` with chosen worlds/rollouts (shuffle-only games).
7. **Export the drift barrier.** `cardlang lab fixtures experiments/rip-current/rip-current.cardlang --traces 200 --views --out experiments/rip-current/play/fixtures/` **[1 cmd]** — action-id/label table, per-trace deal + per-step legal sets/labels + per-player view projections + terminal returns; exhaustive full-tree fixtures for mini-sized games.
8. **Build the page.** Census-fitting games have no engine to write: the kit's `treewalk.js` serves the engine interface straight off the exhaustive fixtures. Otherwise, write the game's JS rules engine (authored work, guided by the `game-artifact` skill) and UI against the kit's engine interface (`init/legal/apply/returns/view`), dropping in kit modules (fixture replayer, PRNG, opponent shells, relay briefing renderer/parser). `cardlang lab replay experiments/rip-current/play/` **[1 cmd]** (wraps the node replayer; loud error naming node if it's absent) must pass every fixture — legal-set, label, view, and returns equality at every step — plus opponent parity and relay round-trip checks. Also runnable as a browser test page.
9. **Publish.** `cardlang lab build experiments/rip-current/play/rip-current.template.html` **[1 cmd]** — inlines fonts/assets and the generated tables, injects the CSP meta, refuses external references, enforces the size budget, stamps the footer with the benchmark claim and fixture-pass provenance. Output: one `.html` file.
10. **Report.** `REPORT.md` cites `results.json`, `opponent-bench.json`, and the fixture-pass stamp. Done.

## The generic terminal view (`cardlang play`)

One plain-text frame per decision, assembled **only from derived information** — the same per-observer machinery that derives information sets, so the UI cannot leak hidden state *by construction*, for any game, with zero per-game code:

- **Header**: game name, hand number, current phase, whose turn.
- **Public state**: the score table and public state variables.
- **Shared zones**, rendered per their declared projections (`observe.view_of`): `identity` → the cards, `count_only` → a count, `trivial` → omitted. The current trick, discard tops, table piles all fall out of this.
- **Your zones**: your hand, sorted by the game's declared `ranking`.
- **Opponents**: name + whatever their zones project to you (usually counts).
- **Recent events**: the last K entries of *your* observation log, rendered through the runtime's own event vocabulary (`observe.render`) — "seat 2 played J♣", "seat 3 announced 20".
- **The decision**: numbered legal actions with their canonical labels (the action space's `render_candidate` vocabulary — the exact strings the solvers and fixtures use). Multi-pick decisions present as sequential single picks, mirroring how `ReplayChooser` decomposes them in the global action space.

A mid-trick frame, roughly:

```
hearts — hand 3 · phase play · your turn                    you are seat 0
scores   seat0 13   seat1 4   seat2 22   seat3 9

trick     seat2 J♣ · seat3 2♣
players   seat1 [7 cards]   seat2 [6 cards]   seat3 [6 cards]
hand      ♣ 9 K   ♦ 4 J   ♥ 3 8 Q   ♠ 2
recent    seat2 played J♣ · seat3 played 2♣

play — choose 1 of 2:   [1] 9♣   [2] K♣        (u undo · ? log · q quit)
>
```

ANSI color and unicode suit glyphs when stdout is a tty; `--plain` / `--ascii` opt-outs; stdlib only.

**Customization is a seam, not a feature, in P0.** The renderer is a small protocol — `render(view: SeatView, decision) -> str` — with `PlainRenderer` as the shipped default. Later renderers slot in without touching the session loop: per-game display *hints* (zone ordering, grouping, compact glyphs) passed as data, a verbose teaching mode, a solver-annotated mode that overlays lab policy output on the menu. A DSL-level `presentation` block is explicitly **deferred**: it would be new grammar surface (full surface-totality cost) for pure cosmetics; trigger to revisit is the first game whose generic frame is genuinely unreadable (likely a positional/solitaire layout).

The `SeatView` value is also the natural precursor of the artifact kit's `briefingData` (opponent kit d renders the same family of facts); convergence of the two is a named promotion candidate once both exist.

## Phases

Effort legend: **S** ≤ half a day, **M** 1–3 days, **L** multi-day. "Extracted" names the existing source; "new" means written fresh.

### P0 — The designer CLI: `check` / `list` / `run` / `simulate` / `play`

Lands first and independently: it needs nothing from the lab phases, runs entirely pyspiel-free, and every later phase dogfoods through it. Today the CLI stops at static checking; playing even a random game means authoring Python. Every ingredient already exists as a seam: the chooser interface (`Chooser = (player, candidates, n) → picks`, `cardlang/runtime/chooser.py`), `play_game`'s tracer/observer hooks, per-observer zone projections (`observe.view_of`) and event rendering (`observe.render`), and the pyspiel-free replay core (`cardlang.openspiel.replay.run: (path, seed, history) → Pause | Terminal`, where `Pause` carries the actor, the sorted legal action ids, the live world, and every player's observation log).

- **CLI restructure** (`cardlang/cli.py`): argparse subcommands `check` (today's behavior, `--emit-ir` intact), `list`, `run`, `simulate`, `play`; later phases add `lab` (P2) and `new` (P4). Compat rule, deterministic: first arg a known subcommand → subcommand; else an existing path → implicit `check` (so `cardlang docs/games/hearts.md` and every doc snippet keep working); else a loud error naming both readings. The three CLI tests and `test_doc_snippets` update in the same change. **(S)**
- **Name resolution + packaged corpus**: a bare name (`hearts`, `gin-rummy`) resolves stem-wise through the adapter registry (`cardlang/openspiel/registry.py`) to a corpus copy shipped as package data at `cardlang/games/*.cardlang` (`[tool.setuptools.package-data]` already ships `stdlib/*.cardlang` — same mechanism); anything path-shaped stays a path. The packaged copy is mechanical, never edited: the existing two-sided registry↔glob pin (`tests/test_typecheck_corpus.py`) extends to a three-way byte-identity pin (docs/games ↔ registry ↔ packaged copy) whose failure message contains the one-line sync command — drift is a red test, not a stale wheel. `cardlang list` prints every resolvable name with player count from the parsed game header. Alternative considered and rejected: relocating the canonical `.cardlang` into the package — `docs/games/` is the corpus home by doctrine (CLAUDE.md); the package carries the mirror. **(M)**
- **`cardlang run <game> [--seed N] [--trace] [--json]`** — one full seeded game, all seats on the random chooser; prints per-hand results and final scores/winner; `--trace` narrates the tracer + observation events through `observe.render` (the same closed vocabulary the proofs pin — no parallel English). Thin wrapper over `play_game`. **(S)**
- **`cardlang simulate <game> -n 1000 [--seed N] [--json out.json]`** — N seeded playouts, aggregate report: per-seat score mean ± stderr, win split, hand lengths, decision counts, legal-set-size histogram. This is `smoke.py`'s shape check made universal and runtime-direct; when the battery lands (P2), its adapter-based smoke tier cross-checks these numbers — a free differential between the two execution paths. **(S–M)**
- **`cardlang play <game> [--seat 0] [--seed N] [--vs random]`** — interactive play on the replay core, not a parallel loop: the session *is* `(seed, history)`; on the human seat's turn, render the frame and read a pick; other seats consult the opponent policy. P0 ships `random` only, but the **opponent-spec grammar** and its resolver registry land here as the seam: `--vs SPEC` fills every non-human seat, `--vs 1=SPEC,2=SPEC,...` assigns per seat, and a spec is either a registered kind or a generated-AI file. P2 fills the registry with generated-AI files (trained or solved `brain.json`, made by `cardlang lab train` — `play` seats brains, it never makes them), P3 with `opponent.py` / `policy.json` / `pimc` and the external/LLM seats (`cmd:` / `llm:` / `relay`). The human is just another policy over `Pause`, so `play` and the arena share the seat interface. Because state is `(seed, history)`: **undo is history truncation** (`u`), and `--save FILE` / `--resume FILE` are a serialized pair of numbers **(S)**. What you playtest is byte-for-byte the world the solvers, fixtures, and proofs see — same action ids, same labels, same views. **(M)**
- **`cardlang/tui/`** — `view.py` (SeatView assembly from projections + obs log + public state), `render.py` (`Renderer` protocol + `PlainRenderer`), `loop.py` (the session). Design per "The generic terminal view" above. Strict-mypy, no new dependencies. **(M)**
- **Leak pin (the UI's soundness test)**: `SeatView` is constructed exclusively from the observing seat's projections, its own observation log, and public state — the raw world never reaches the renderer (correct by construction: the value simply has no hidden fields). Pinned metamorphically by reusing the openspiel_ready partition machinery: two worlds indistinguishable to a seat must render identical frames. **(S–M)**
- Tests: golden rendered frames for one corpus game (seeded, `--plain`), CLI exit codes, the name/path/unknown resolution matrix, `simulate` determinism per seed (PYTHONHASHSEED pinned where scores are exact). **(M)**

Acceptance: `uv run cardlang play hearts` from a fresh checkout reaches an interactive hand with pyspiel absent; `cardlang run`/`simulate` reproduce seeded output byte-identically; the three-way corpus pin is red on any drift; gates green; zero per-game branches in CLI or TUI.

### P1 — One lab substrate (kill the glcommon/utcommon fork)

The registration/memo boilerplate is at its second instance, which is exactly the repo's promotion trigger.

- **`cardlang/lab/register.py`** — extracted from the two `*common.py` files. One `register_experiment(path, *, short_name, num_seeds, utility)` covering both shapes: configurable seed count at the chance root (1 for shuffle-free, sampled for dealt games), declared utility (`zero_sum` / `constant_sum(k)` / `general`) mapped to `pyspiel.GameType`, and an empirical utility verification (N random playouts must sum as declared). **(M)**
- Replace the monkey-patching memos with a first-class cached path: the lab's `_State` subclass calls a module-level `lru_cache`d runner keyed `(path, seed, history)` directly, and memoizes the infostate string in an explicit bounded dict — no mutation of `cardlang.openspiel.replay` or `CardlangState`. **(S)**
- Retarget both experiments: `glcommon.py`/`utcommon.py` become thin shims. **(S)**
- `pyproject.toml`: extend the pyspiel mypy override to `cardlang.lab.register`. **(S)**
- Tests in `tests/test_lab_register.py` (skip-if-no-pyspiel): registration round-trip on a tiny fixture game, utility misdeclaration refused loudly, memo purity. Needs a **nano fixture game** at `tests/fixtures/nano-duel.cardlang` (a 2-3 decision shuffle-free game, walkable exhaustively in tests) — also serves P2/P3 tests. **(M)**

Acceptance: gates green; `proofs.py` and a 20-iteration `solve.py` run reproduce prior outputs through the shims; no import of `experiments/` from `cardlang/` or `tests/`.

### P2 — The size-tiered, game-agnostic evaluation battery

- **`cardlang/lab/exact.py`** — extracted from `analyze_mini.py` + `solve.py`: budgeted census (node/time caps decide tier), CFR+ with exploitability trend, expected value, reach-weighted strategies, mixedness. Green-Lane-specific label assumptions removed from the core. **(M)**
- **`cardlang/lab/naive.py`** — extracted from `analyze_heuristics.py`/`analyze_exploit.py`: `joint_value`, best-response exploitation, and a *pluggable* naive-rule grid — generic defaults (uniform, first-legal) plus rules the experiment's `probes.py` registers. The two-column "vs equilibrium / vs best response" table becomes standard output whenever the tree fits. **(M)**
- **`cardlang/lab/probes.py` + `cardlang/lab/obslog.py`** — extracted from `analyze_undertow.py`: shape, decision-liveness, and a typed accessor API over the observation log so probes stop regexing raw tuples (the event vocabulary is closed — the accessor can be complete against it, pinned). Undertow's tide probe rewrites onto this API but stays in `experiments/undertow/`. **(M)**
- **`cardlang/lab/sampled.py` + `cardlang/lab/arena.py`** — extracted from `analyze_full.py` + `analyze_undertow.py`: MCCFR training (2p outcome-sampling and n-player rotation), weak/strong gradient, head-to-head arena (seats alternating/rotating, mean ± stderr). **(M)**
- **`cardlang lab train <game> --mccfr N --out brain.json`** — makes the probe tier's trained policy a first-class **generated-AI file**: the MCCFR average policy, keyed by runtime infostate string (fine inside the runtime; P3's `policy-export` exists for the JS-shippable canonical form), stamped with the source hash of the game it was trained on and its training provenance (steps, seed). The exact tier's CFR+ solution saves the same way, so a solved mini's `equilibrium` is also a file you can sit across from. **(S–M)**
- **One opponent-spec registry**, shared by `cardlang play --vs` and `cardlang lab arena --vs`, resolving the P0 grammar — with one deliberate asymmetry: **`play` seats brains, it never makes them.** Play-side atoms are `random`, any `.json` generated-AI file, and (P3) `.py` opponent policies, `pimc`, and the external/LLM seats (`cmd:` / `llm:` / `relay` — opponent kit e); a training kind handed to `play` is a loud rejection pointing at `cardlang lab train`, because the only path to an AI opponent runs through the flow that stamps provenance, checkpoints, and a benchmarkable identity. Training kinds exist solely as **arena reference opponents** (`equilibrium`, `best_response`, `mccfr:<steps>`) — measuring instruments in a batch, budget-stated context under the long-run contract. The registry owns the *atoms*; each command owns its list semantics (`play`: one spec fills all non-human seats, `1=…,2=…` assigns per seat; `arena`: one benchmark run per listed opponent). Closed registry, misuse-probed: an unknown kind is a loud error listing the registry, and a generated file whose embedded source hash doesn't match the game it's loaded against is a **refusal, never a silent uniform fallback** — a stale brain must not impersonate a benchmarked one. **(S–M)**
- **The long-run contract** — binding on every lab subcommand that can exceed ~a minute (`eval`'s probe tier, `train`, `arena`, large fixture exports). Motivating instance, measured (`undertow/REPORT.md` §4): Undertow's 60k-iteration MCCFR was killed after **two hours at under 10k iterations** (>700 ms/iteration on the re-simulation adapter, structural O(length²)); Green Lane's same algorithm ran 13–21 ms/iteration and finished 120k in 42 minutes. The contract: (1) **estimate before commit** — a short calibration burst extrapolates per-stage cost; the stage plan with ETAs prints before any work starts, and past a threshold (~2 minutes) an interactive run asks to proceed while a scripted run requires `--yes` — Undertow's run would have announced "~12 h at the measured rate" instead of silently consuming two. (2) **Heartbeats carry measurements** — rate-limited stderr lines with iterations/sec plus the live metric (exploitability at last checkpoint, arena winrate ± stderr so far), so the trend is readable in flight and an early kill still informed. (3) **Partial results are kept** — `eval` writes `results.json` stage-atomically, marked `"partial": true` until complete; an interrupted battery loses only the stage in flight. (4) **Checkpoints are brains** — `train` rewrites `--out` periodically (atomic replace, provenance updated with steps-so-far); every checkpoint is a loadable generated-AI file, so you can `play --vs` the half-trained brain, retained checkpoints give the weak/strong gradient for free, and `--resume` continues one (source-hash checked). (5) **Wall-clock budgets** — `--minutes M` accepted wherever a step count is. (6) **The honest ceiling** — when calibration says the requested budget is out of reach on the replay adapter, the run refuses with the measured rate and records the ceiling REPORT-ready; the fixture-pinned speed-twin pattern (`undertow/fast_sim.py`) is the recorded one-instance answer and promotes at its second instance, per doctrine. **(M)**
- **`cardlang/lab/proofs.py`** — generalized from Green Lane's: the four experiment-grade checks with the game-specific node classifier replaced by an observation-delta classifier (a decision is concealed for observer Q iff Q's obs-log delta is identical across alternatives — derived, not configured). Does **not** touch `tests/openspiel_ready/`; overlap recorded as a promotion candidate. **(M)**
- **`cardlang/lab/__main__.py` + `report.py`** — the one-command driver: auto-tier, run battery + proofs, write one versioned results JSON. **(M)**
- **The `cardlang lab` subcommand family** — every lab-side tool is a subcommand, so the designer never leaves the one CLI. This phase ships `cardlang lab eval <game>` (the battery; a bare game path is shorthand for `eval`, by the same deterministic first-arg rule as the top level), `cardlang lab arena`, and `cardlang lab train`; P3 grows `fixtures` / `policy-export` / `replay` / `build`. Each subcommand is a thin wrapper over its module's main, and `python -m cardlang.lab.<module>` stays equivalent. Dependency errors are pointed and per-subcommand: name the `openspiel` extra when pyspiel is missing (the rest of the CLI never requires it); name node where `replay` needs it. **(S)**
- Tests over the nano fixture game for every module. **(M)**

Acceptance: `cardlang lab eval` reproduces Green Lane mini's recorded census and exploitability trajectory; selects the probe tier on Undertow and reproduces the liveness table's shape; gates green; zero game-specific labels in the battery.

### P3 — The artifact kit: fixtures, JS harness, opponent kit, build

- **`cardlang/lab/fixtures.py`** (new; precedent: `tests/test_differential_gops.py`'s lockstep walk): export (1) the action table (every reachable global action id + label); (2) per-trace: seed, post-setup deal, per-step actor, legal ids + labels, chosen action, optional per-player view projections (zone views, public state, obs-log delta — the briefing ground truth), terminal returns; (3) `--exhaustive` full-tree fixtures when the census fits. Trace policies: random plus registered policies (solver-driven traces reach states random play misses). Schema versioned; provenance embedded. **(M)**
- **`experiments/_kit/`** (new, JS/HTML only): `replay.js` node fixture replayer against the kit engine interface (`init/legal/apply/returns/view`) + `replay.html` browser variant; `treewalk.js` — the generic engine-interface implementation over exhaustive fixtures, so census-fitting games ship **zero per-game rules code**; `prng.js` + `cardlang/lab/prng.py` (one deterministic PRNG both sides, cross-checked); opponent shells `tabular.js` / `heuristic.js` / `pimc.js` / `relay.js` (generalized from the Green Lane template). **(M)**
- **`cardlang/lab/policy_export.py`** (new): exact-tier average policy → `policy.json` keyed by a canonical key (player + own-view projection + rendered own-choice history — never the runtime infostate string), injectivity asserted over all solved infosets, truncation rules, and reload-verification (recompute exploitability from the exported table; ship only on match). **(M)**
- **`cardlang/lab/parity.py`** (new): K exported decision points; the JS twin must reproduce the Python twin's distribution and sampled action exactly (IEEE-754 both sides, operation order pinned). **(S–M)**
- **`cardlang/lab/pimc.py` + `forced_deal.py`** (new): Python PIMC twin for hidden-deal games — consistent-world sampler (unseen cards, hand counts, voids and reveals from the obs log) + a prescribed-shuffle `Random` so sampled worlds replay through the real runtime. Hard wall: refuse any game whose rng use exceeds the setup shuffle. **(L)**
- **`cardlang/lab/seat_protocol.py` + `cardlang/lab/llm_seat.py`** (new): the versioned JSONL-over-stdio **seat protocol** behind the `cmd:` atom (UCI's architecture — opponent as subprocess, host stays SDK-free — with our own wire), and the stdlib OpenAI-compatible HTTP client behind `llm:`, which also runs standalone as the reference seat-protocol adapter — the worked example for writing your own. The terminal `relay` atom reuses the briefing renderer/legality parser that `relay.js` needs anyway. Spec and contracts in opponent kit (e). **(M)**
- **`cardlang/lab/build_artifact.py`** (new): placeholder inlining, CSP meta injection, refusal of external URLs, size budget, provenance footer (benchmark numbers + fixture-pass stamp). **(S–M)**
- **`cardlang lab` grows `fixtures` / `policy-export` / `replay` / `build`** — one subcommand per tool above, completing the family P2 opened: `replay` wraps the node fixture replayer (`experiments/_kit/replay.js`) so the drift gate is runnable without remembering the kit path, `build` runs `build_artifact`. Same thin-wrapper rule; `python -m` forms stay equivalent. **(S)**
- **`cardlang play --vs` wiring**: the opponent-spec registry (P2) extends with the opponent kit's Python twins — `opponent.py` policies, exported `policy.json` tables, `cardlang.lab.pimc` — and the external/LLM seats of (e): `cmd:` subprocess seats on the seat protocol, the bundled `llm:` client, terminal `relay`. Every AI the kit generates, benchmarks, or bridges is seatable in the terminal, alone or in per-seat mixes. One policy interface over `Pause` shared by the arena and the human session: "benchmark it" and "play it yourself" are the same object. **(S)**

## The faithfulness decision

**Recommendation: deterministic *data*, authored *code*, fixtures as the converter between them. Census-fitting games ship zero rules code — a generic tree-walker runs the exhaustively exported game. Larger games get a per-game authored port (LLM authorship under the `game-artifact` skill is the expected mode) verified by promoted differential fixtures. The JS IR interpreter and the in-page WASM runtime stay recorded candidates behind explicit triggers.**

Evidence (measured):

- The corpus-wide IR uses **57 distinct node kinds** and **73 stdlib calls** (mostly per-game primitives, climb engines, auction vocabularies); a corpus-covering JS interpreter ≈ a port of ~2,900+ lines of runtime semantics. Not the use case.
- The experiment games are small: Green Lane 27 IR kinds, one stdlib call, no `round`, ~70 lines of hand-written JS engine; Undertow 32 kinds, 3 stdlib calls, one `round` + one library rule. An experiment-class interpreter still needs the expression evaluator, statement executor, phase driver, rules engine, trick mechanic, visibility — **1.5–2.5k lines of JS** vs **~100–250 per hand-ported engine**: a 10–20× multiple that pays only across many games.
- The IR is a sidecar today (runtime and adapter consume the checked AST; IR fidelity pinned only by goldens). A JS IR-walker would be the first *executing* consumer — a second semantic seam that would itself need differential gating. **Fixtures are the floor under every option.**
- The hybrid "generate legality from IR" still requires ~60% of the interpreter (expressions + rules engine) and misses that for some games the *effects* are the substance. Fixtures cover both halves uniformly.
- What survives from the hybrid: a tiny exporter emitting the action-id/label table, deck composition, ranking order, choose ceilings, move-type names — JS consumes these as constants, eliminating the transcription-drift class at near-zero cost.
- **The fully deterministic path exists for small games and is claimed, not gated**: when the census fits, the `--exhaustive` fixtures ARE the complete game — the kit's `treewalk.js` (written once, generic) serves the engine interface straight off the exported tree, and the artifact contains **no per-game rules logic at all**. Faithfulness for census-fitting games is a construction, not a verification: the data is the adapter's own output.
- **Authored code is made safe by the gates, not by the author**: fixtures diff legal sets, labels, views, and returns at every step, so human-vs-LLM authorship is irrelevant to soundness. That is why an authoring skill plus gates beats an interpreter at current scale — two shipped instances ran ~70 and est. 150–250 engine lines against a 1.5–2.5k-line interpreter that would itself need differential gating.
- **In-page WASM runtime (Pyodide) — the other zero-second-seam option, recorded**: ship the real Python runtime compiled to WASM; perfect fidelity by construction, no port at all. Costs: the page (~10 MB+ vs Green Lane's 82 KB), seconds of startup, and opponent-compute throughput (the fast_sim lesson bites ~2–5× harder under WASM). Trigger: a game that defeats both the tree-walker (census too big) and a sane port (>~500 lines), or an explicit decision to relax the size budget.
- Doctrine: one shipped artifact today; the fixture format has two-instance demand (both experiments will carry artifacts) and promotes now; the interpreter has zero instances of demonstrated recurring cost. **Trigger to revisit**: the third artifact-bearing game, or the first fixture-escaping rules divergence in a shipped artifact, or the first engine port exceeding ~500 lines.
- **When the trigger fires, the build is not the corpus-covering interpreter — it is the walled partial compiler.** A game's demand on the closed registries is statically computable (which IR node kinds and stdlib calls it uses: Green Lane 27/1, Undertow 32/3), so a per-game transpiler can be **total over a declared subset** of those registries, pinned complete against them by a static test, and **loudly refuse** any game outside the subset ("uses `round`; not yet compilable — author the engine or reduce"). That is deferred-and-walled — the doctrine's approved shape — and its cost grows with demand, kind by kind with a completeness ledger, instead of 1.5–2.5k lines up front. A compiled engine is still a second executing seam: fixtures remain the floor beneath it, exactly as beneath an authored one.

Fixture strength requirements: exhaustive full-tree fixtures whenever the census fits; otherwise random **plus** solver-policy-driven traces; per-step legal *sets* and labels; per-player view projections (information handling is diffed, not assumed); one-command regeneration with provenance.

## Opponent-kit specifics

Common substrate: every opponent's Python twin runs against the adapter via `lab/arena.py`; every JS port passes a parity or reload gate before `build_artifact` stamps the page.

**(a) Exported tabular policy** (small games only): inputs = exact-tier average policy + census + reachable-infoset list; canonical key = player + own view projection + rendered own-choice history (never the runtime infostate string); injectivity asserted at export; JS `tabular.js` with loud counted uniform fallback (zero hits required on exhaustive fixtures); measured claim = reloaded-table exploitability + arena vs uniform, printed in the artifact footer.

**(b) Solver-informed parametric heuristic**: inputs = equilibrium marginals / opening books + the naive-grid floor + sweep lessons; Python twin mandatory (`opponent.py`, explicit parameters, tuned by arena sweeps); benchmark = deviation loss vs equilibrium AND vs exact best response (exact tier) or arena vs MCCFR-strong/random (probe tier); JS `heuristic.js` = pure `(view, params, prngFloat) → distribution` with params as generated JSON; parity gate on K exported decision points. (The shipped Green Lane officer has no Python twin or measured claim yet — the P3 retrofit closes that.)

**(c) Determinized Monte Carlo / PIMC** (hidden-deal games): needs the fixture-proven JS engine + parameters chosen by benchmark; consistent-world sampler (unseen cards, hand counts, voids from failure-to-follow, reveals); Python benchmark replays sampled worlds through the real runtime via prescribed shuffles (valid exactly for shuffle-only games; loud wall otherwise); arena vs random / heuristic / trained MCCFR; JS parity on sampler outputs + sampler-soundness property tests; latency budget <~1s/decision in the test page.

**(d) LLM by relay**: inputs = per-state opponent-view projections + action label table + log-line vocabulary; JS `relay.js` renders a structured `briefingData` (pronoun flip in the renderer, never the data) and parses replies with legality validation; measured claim is **faithfulness, not strength** — briefingData equals the fixture's view projection byte-for-byte at every decision; round-trip totality over every legal action; a no-leak assertion that briefingData reads only `view(state, opponent)`.

**(e) LLM & external seats in the terminal** (`play`/`arena` only — the shipped page stays relay-only, per the no-network non-goal). The architecture is the **seat protocol**: cardlang spawns the opponent as a subprocess and speaks versioned JSONL over stdio — one `{"type": "decision", "view": …, "legal": […], "labels": […]}` line per decision, one `{"type": "act", "action": <id>}` line back. This is UCI's architecture (chess GUIs drive engines as subprocesses over a tiny stdio protocol and bundle no engine code) with our own wire — UCI itself is chess-vocabulary text and carries nothing we need. `--vs cmd:"<program>"` therefore seats anything written in any language with any SDK, the package ships zero provider code, and subscription CLIs work with no API key at all (`--vs cmd:"claude -p"` rides the user's existing login). Two shipped adapters sit on top: **`llm:<model>[@<base-url>]`** — a ~100-line stdlib (`urllib`) client speaking the de-facto OpenAI-compatible chat wire format that every major provider and local runtime accepts (OpenAI, the Anthropic and Gemini compatibility endpoints, OpenRouter, Ollama/vLLM/LM Studio), key from environment only — never argv (visible in `ps`), never provenance; and **`relay`** — the zero-network floor: the briefing prints in the terminal, the reply is pasted back (the artifact panel's twin, same contract, works with any free chat UI). Contracts, all inherited: the prompt is a pure render of `SeatView`, so (d)'s faithfulness/no-leak claim carries over verbatim; an illegal or unparseable reply gets a bounded re-prompt naming the violation, then a **counted, loud** fallback — never silent; every LLM-seated session writes a transcript sidecar (prompts, replies, chosen actions), so the game replays as `(seed, history)` even though the policy is non-reproducible — bench provenance marks it so, recording model + endpoint host; an LLM seat is benchmarkable like any other spec via `arena` (a measured strength claim for an LLM on your game), and arena-scale LLM runs get a cost estimate up front (games × decisions × price/call) under the long-run contract. Rejected alternative, recorded: bundling per-provider SDKs (or `litellm` as an extra) — dependency scope and churn for what the compat wire format and the seat protocol already cover.

## Risks and open questions — each with its cheapest probe

1. **Canonical-key injectivity for tabular export** — probe: compute the candidate key for all 144 solved Green Lane mini infosets, diff against the runtime partition (minutes).
2. **Observation-delta classifier for generalized proofs** — probe: implement and compare against `is_ship_node` on Green Lane; must classify nothing concealed at Undertow's public trick plays.
3. **Fixture size with `--views`** — probe: export 50 Undertow traces with views, measure; set cap/compression + commit policy.
4. **JS/Python float parity** — probe: 100 random officer-formula evaluations in node vs CPython, compare bit patterns.
5. **PIMC forced-deal wall** — probe: an instrumented `Random` counting draw sites per game (doubles as the wall's implementation).
6. **Exploitability acceptance envelope** (constant-sum vs general-sum) — probe: one-line check of stock `exploitability` vs `nash_conv` on toys; pin which metric each tier reports.
7. **Node in CI** — probe: confirm runner availability once; test is `skipif` node absent either way.
8. **Proof-harness duplication** (`lab/proofs.py` vs `tests/openspiel_ready/harness.py`) — deliberate for now; probe: after P2, list actually-shared signatures; ≥3 copies fires the promotion ledger.
9. **Packaged-corpus drift** (wheel vs `docs/games/`) — the three-way byte pin is the wall in-tree; wheel staleness only exists at publish time — probe: a pre-publish check that rebuilds the mirror and asserts a clean `git status` before `uv publish`.
10. **Terminal menus at climb-game scale** (Big Two/Tichu legal sets can run to hundreds of combinations) — probe: `cardlang simulate` already records the legal-set-size histogram; read the corpus maxima off it and size the mitigation (paginated menu + type-to-filter on card names) before building it.
11. **ETA reliability** (iteration cost drifts as trees deepen and the replay memo warms or shatters — a cheap early burst can flatter the true rate) — probe: retrodict the two recorded runs from their logs (Undertow >700 ms/it, Green Lane 13–21 ms/it finishing 120k in 42 min): does a 1k-iteration calibration predict each actual within ~2×? Data already on disk; minutes. Sets the safety factor the printed estimates carry.
12. **LLM reply legality rate** (an LLM seat is unusable if the model can't reliably return a legal action) — probe: pilot ~100 decisions of a cheap model over the hearts and Green Lane briefings; count parse and legality failures. Sets the re-prompt budget and the reply format (free-text label vs required menu index).

## Future runtimes and targets (recorded, not scheduled)

Everything below rides the property that made OpenSpiel an adapter rather than a rewrite: the kernel reduces any game to `(seed, history)` + derived per-observer views + a closed action space, so any target that consumes "state = replayable history, observation = derived view, actions = enumerable ids" is an adapter. **A secondary objective of the project is to be offerable to MARL research** — a cardlang game file should be a first-class environment in the ecosystems those projects already use. **The top three rows are the ones of most interest.**

|---|---|---|---|---|
| **RLCard** | Python RL toolkit specifically for card games (Hold'em, Dou Dizhu, Gin, UNO, Mahjong) | Low — its env API is simpler than OpenSpiel's; sits on `Pause`/SeatView | Their agent zoo (DMC/DouZero-style, NFSP, CFR) and the card-game RL community | **Top-3 interest** |
| **PettingZoo** (+ Gymnasium) | The Farama standard for multi-agent RL (AEC API); Gym falls out by freezing all but one seat | Medium — needs the tensor encoder | The modern MARL toolchain: Tianshou, RLlib, CleanRL, SB3 — the secondary objective's front door | **Top-3 interest** |

**Shared prerequisite for the top three: a derived tensor encoder.** The adapter today is strings-only (`cardlang/openspiel/game.py` declares `provides_information_state_tensor=False`), so the nearest-term item is not a new target at all: one observation-tensor encoding derived from the zone projections + event vocabulary completes the existing OpenSpiel target (unlocking its own deep RL — Deep CFR, NFSP, R-NaD) and is the same encoder the RLCard and PettingZoo adapters consume.

**Pinned scoped item — the derived tensor encoder.** Deliberately written as an *external-friendly* unit: well-bounded, zero kernel changes, zero per-game code, high ecosystem value — a natural candidate for a **grant or sponsorship**, or for an outside contributor to build and submit; the acceptance list below is the review bar either way.

- **Consumes what exists.** The information state is already a pure function of three derived inputs — zone views through declared projections, public state variables, the per-observer observation log (`cardlang/openspiel/infostate.py`); the tensor is a second rendering of the same function, numeric instead of textual. Every static size the layout needs is already derived per game: the card block (from the declared deck), `num_distinct_actions` (the action space), `max_game_length` (already feeds `GameInfo`), seating, zone list, phase set, choose ceilings. `_render`'s sorted-collection canonicalization means multi-hot vectors are exactly faithful to string semantics, not an approximation.
- **Build — four pieces, all closed-domain with walls.** (1) A per-game **layout deriver**: declarations → a fixed tensor shape computed before play — zone segments by projection level (identity → card-block multi-hot, `count_only` → bounded count, trivial → nothing), state-variable segments, turn/phase one-hots, and an event-history segment padded to the derived max length (perfect recall; the observation tensor is the same layout minus history). (2) A numeric encoding dispatch per **value shape**, mirroring `_render`'s (int / str / Card / dict / list / StructValue), same loud refusal beyond the declared shapes. (3) An encoding dispatch per **event kind**, exhaustive against the closed event vocabulary and statically reconciled with it (build on the obslog accessor, P2). (4) The one genuinely new derivation: **bounded domains for integer state variables** — from end conditions and deck arithmetic where derivable, a loud wall naming the variable where not; no new grammar surface.
- **Acceptance.** Tensor equality on every indistinguishable pair the partition harness enumerates; the soundness matrix extended per-cell (a `count_only` zone leaks no card identity into any coordinate); tensor-is-a-function-of-the-log by construction; fixed-shape fuzz across seeds; `provides_information_state_tensor` / `provides_observation_tensor` flipped to `True` with adapter agreement green; completeness ledger over the three dispatch registries + surface-totality audit. **(M — the integer-bounds derivation is the one research-flavored bit and the likely source of the first walls.)**

The gate, unchanged from doctrine: every target is corpus-first (built against a witnessed need, never speculatively); ships per-target faithfulness proofs on the `openspiel_ready` pattern (indistinguishability, soundness matrix, adapter agreement); derives its observations from the same projections and event vocabulary — hand-authored per-target encodings would quietly reintroduce the per-game-observation debt the kernel migration killed; and runs a lockstep differential against the Python runtime, as the JS engines do via fixtures. Cautions recorded: virtual-tabletop export is layout + visibility only (rules stay human-enforced — a table, not a runtime; no faithfulness claim beyond setup), and BoardGameArena is a non-target (closed platform, handwritten per-game submissions).

**Pinned scoped item — theory-of-mind research support.** The system's differentiator for ToM work: each player's knowledge is *derived and certified* (the per-observer logs + projections the `openspiel_ready` proofs pin), where most ToM harnesses hand-author "what the agent should know" per game. Much is already carried by items above — bespoke probe games are the quickstart design loop; LLM seats with provably leak-free briefings and saved transcripts are opponent kit (e), and the faithfulness contract is exactly a study's "the model was told only what it should know" defense; counterfactual worlds are `(seed, history)` replay + prescribed shuffles; equilibrium/best-response baselines are the exact tier. Two pieces are new:

- **The epistemic query API** — promote the consistent-world machinery from opponent-internals (`pimc.py`) to a first-class, proof-backed research surface: `worlds(seed, history, observer)` — exact enumeration when the census fits, sampled with stated coverage otherwise — plus posteriors over hidden facts, as scoreable ground truth for belief questions. Shares the sampler's hard wall (shuffle-only games for the sampled tier) and its soundness property tests.
- **The belief-probe harness** — the seat protocol gains a `probe` message: at a paused decision, ask the seated model belief questions (not just action choices), score replies against the derived posterior, and record both in the transcript sidecar. Composes with (e) unchanged; the arena can then report belief-accuracy alongside strength.

Higher-order knowledge (what A can know about B's knowledge — the partition construction iterated) is recorded as a research-grade **candidate**, not scoped. Corpus-first applies: build these when the first actual study runs. Like the tensor encoder, this is grant-shaped work — certified epistemic ground truth is the pitch.
